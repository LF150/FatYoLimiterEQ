Foreseen Problems

1. “0 attack” versus true hard limiting. A real-time limiter cannot both react with literally zero lookahead and guarantee that no sample/true-peak exceeds the ceiling. A one-sample or small lookahead can provide much stronger protection, but introduces latency.

2. 3-second release. This is deliberately slow. It may cause audible level recovery after large EQ boosts. That is useful for the proposed “collar” behaviour, but it needs listening tests.

3. EQ gain can create very large internal peaks. The EQ engine needs sufficient floating-point headroom before the limiter. The limiter must not be used to hide unstable DSP or denormal/NaN conditions.

4. True-peak versus sample peak. A sample ceiling at -3/-6 dBFS is not automatically a true-peak ceiling after reconstruction. Oversampling or a true-peak detector should be part of the production design.

5. User expectation. The switch should never silently change perceived output level when OFF; ON should behave predictably as a protective output contract rather than a “loudness” control.

6. Band interaction. Six boosts can combine into considerably more level than any individual band suggests. The display should therefore show the combined curve and the output meter should show actual post-EQ level.
